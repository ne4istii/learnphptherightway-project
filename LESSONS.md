## Урок 36 — классы и объекты

- `class Transaction` описывает, каким будет объект. `new Transaction(300, '...')` создаёт конкретный объект.
- `__construct()` получает начальные значения. `$this` внутри методов означает «этот объект».
- `private` закрывает прямой доступ к свойству снаружи. Сумму читаем через `getAmount()`.
- `addTax()` и `applyDiscount()` меняют сумму и возвращают `$this`, поэтому вызовы можно соединить через `->`.
- `__destruct()` в нашем примере печатает сообщение при уничтожении объекта.

Пример: `300 → +8% = 324 → −10% = 291,6`.

Дополнительно: в `dynamic-class.php` имя класса хранится в строке, а `object-casting.php` показывает преобразование значений в объект.

Код с простыми комментариями: [тег `lesson-36-commented`](https://github.com/ne4istii/learnphptherightway-project/tree/lesson-36-commented).

## Урок 37 — свойства в конструкторе и `?->`

- Запись `private float $amount` прямо в параметрах конструктора сразу создаёт свойство и сохраняет переданное значение. Повторять объявление свойства и присваивание уже не нужно.
- `?Customer` означает: значение может быть объектом `Customer` или `null`.
- `?->` безопасно продолжает цепочку: если слева `null`, результат тоже `null`, а оставшаяся часть цепочки не выполняется.
- `??` задаёт запасное значение, когда результат слева равен `null`.

В нашем примере без клиента видно «Профиль не найден», а с клиентом и профилем — `42`. Классы `Customer` и `PaymentProfile` добавлены для запуска этого примера.

## Урок 38 — пространства имён (`namespace`)

- Два класса могут называться `Transaction`, если их полные имена различаются: `PaymentGateway\Paddle\Transaction` и `PaymentGateway\Stripe\Transaction`.
- `namespace` задаёт полное имя класса. Папки удобно называть так же, но само имя папки namespace не создаёт.
- `require_once` загружает файл с классом, а `use` позволяет писать короткое имя вместо полного. В следующем уроке автор переходит к автозагрузке файлов.
- В `use` фигурные скобки группируют классы из одного namespace: `use PaymentGateway\Paddle\{Transaction, CustomerProfile};` — то же самое, что два отдельных `use`.
- `as StripeTransaction` помогает использовать в одном файле оба класса `Transaction`.
- Если внутри namespace нужен встроенный класс PHP, его можно указать от корня: `new \DateTime()`.

Пример: открой `http://localhost:8001/namespaces.php` — `var_dump()` покажет объекты из двух разных пространств имён.

## Урок 39 — автозагрузка, PSR-4 и Composer

- `spl_autoload_register()` вызывает нашу функцию, когда PHP встречает ещё не загруженный класс, интерфейс или трейт. Загрузчиков может быть несколько: PHP пробует их по порядку; аргумент `prepend: true` ставит загрузчик в начало очереди.
- В `manual-autoload.php` полное имя `App\PaymentGateway\Paddle\Transaction` превращается в путь `app/PaymentGateway/Paddle/Transaction.php`. `__DIR__` задаёт путь от текущего файла, а `is_file()` не даёт `require` выдать предупреждение при отсутствии файла. Автор приводит `App` к нижнему регистру через `lcfirst()`; мы убираем префикс `App\` и подставляем `app/` — итоговый путь тот же.
- **PSR-4 — правило, по которому загрузчик находит файл класса по его полному имени.** В `composer.json` мы записали `"App\\": "app/"`. Это значит: «если имя класса начинается с `App\`, ищи его файл внутри папки `app/`». Два слеша `\\` в JSON обозначают один слеш `\` в имени класса.

  Например, PHP нужен класс `App\PaymentGateway\Paddle\Transaction`. Composer убирает начало `App\`, получает `PaymentGateway\Paddle\Transaction`, заменяет `\` на `/` и ищет `src/app/PaymentGateway/Paddle/Transaction.php`. В этом файле действительно объявлены `namespace App\PaymentGateway\Paddle;` и `class Transaction`.

  После изменения **самого правила** в `composer.json` запускаем `composer dump-autoload`. При добавлении нового класса в уже настроенную папку `app/` повторять команду обычно не нужно. `use` только сокращает имя класса в PHP-коде; файл находит загрузчик.
- `require vendor/autoload.php` подключает загрузчик Composer один раз. Он находит и наши классы, и классы установленной библиотеки `ramsey/uuid`.
- `composer require ramsey/uuid` добавляет библиотеку и её собственные зависимости. `composer.json` можно создать и командой `composer init`; `composer update` обновляет подходящие версии, `composer remove` удаляет зависимость.
- `require` в `composer.json` — зависимости приложения, `require-dev` — инструменты для разработки и тестов. При `composer install --no-dev` зависимости из `require-dev` не устанавливаются.
- Composer записывает точные версии всех зависимостей в `composer.lock`: его сохраняем в Git. Команда `composer install` берёт эти версии и создаёт `vendor/`; эту папку в Git не добавляем.
- `composer dump-autoload -o` заранее строит карту классов для ускорения загрузки. Новые классы по умолчанию всё ещё находятся через PSR-4; повторный запуск нужен, чтобы добавить их в оптимизированную карту.
- PSR — рекомендации PHP-FIG. PSR-1 и PSR-12 описывают стиль PHP-кода; PSR-4 отвечает за автозагрузку. Автор показывает, что PhpStorm может автоматически форматировать код по PSR-12.

Посмотри оба варианта: [ручная автозагрузка](http://localhost:8001/manual-autoload.php) и [Composer с UUID](http://localhost:8001/composer-autoload.php). После клонирования проекта запусти `docker compose -p learnphptherightway -f docker/docker-compose.yml up -d --build`, затем `docker compose -p learnphptherightway -f docker/docker-compose.yml exec app composer install`.

Код: [тег `lesson-39`](https://github.com/ne4istii/learnphptherightway-project/tree/lesson-39). Видео: [урок 2.5 автора](https://youtu.be/rqzYdHdyMH0).

## Урок 40 — константы класса

- `public const PAID = 'paid';` хранит неизменяемое значение, общее для класса. По соглашению имя константы пишут заглавными буквами. Читать её можно без объекта: `Status::PAID`. `::` называется **оператором разрешения области видимости** (англ. *scope resolution operator*). Здесь он даёт доступ к константе класса.
- У константы может быть видимость `public`, `protected` или `private`. Если ничего не написать, она `public`; автор советует указывать видимость явно. `private` нельзя прочитать снаружи класса.
- Внутри класса `self::PAID` обращается к константе этого класса. `$this` относится к конкретному объекту. Специальная запись `Transaction::class` возвращает полное имя класса с `namespace`.
- Вместо строки `'paid'` в разных местах используем `Status::PAID`: так меньше риск опечатки. Но метод всё ещё может получить произвольную строку, поэтому `setStatus()` отдельно проверяет её по `Status::ALL_STATUSES` и отклоняет неизвестные значения.
- `ALL_STATUSES` — массив-константа: ключи служат допустимыми статусами, значения — подписями для вывода. Автор сначала хранит статусы в `Transaction`, затем переносит их в отдельный класс `App\Enums\Status`.
- В контейнере урока PHP 8.0.2, поэтому `Status` — обычный класс с константами. Встроенный `enum` появился позже, в PHP 8.1.

Пример: [class-constants.php](http://localhost:8001/class-constants.php) показывает `paid`, начальный статус `pending`, смену на `paid`, подпись `Paid` и полное имя класса.
