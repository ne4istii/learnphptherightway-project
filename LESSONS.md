## Урок 36 — классы и объекты

- `class Transaction` описывает, каким будет объект. `new Transaction(300, '...')` создаёт конкретный объект.
- `__construct()` получает начальные значения. `$this` внутри методов означает «этот объект» — как `self` в методах Python; через `$this->amount` обращаемся к его свойству.
- `private` закрывает прямой доступ к свойству снаружи. Сумму читаем через `getAmount()`.
- `addTax()` и `applyDiscount()` меняют сумму и возвращают `$this`, поэтому вызовы можно соединить через `->`.
- `__destruct()` в нашем примере печатает сообщение при уничтожении объекта.

**Python:** `Transaction(...)` создаёт объект без слова `new`; `__init__` ближе всего к PHP `__construct`, а Python `self` — к PHP `$this`. Для `__destruct` ближайший по назначению `__del__`, но на его вызов не стоит опираться в важной логике.

Пример: `300 → +8% = 324 → −10% = 291,6`.

Дополнительно: в `dynamic-class.php` имя класса хранится в строке, а `object-casting.php` показывает преобразование значений в объект.

Код с простыми комментариями: [тег `lesson-36-commented`](https://github.com/ne4istii/learnphptherightway-project/tree/lesson-36-commented).

## Урок 37 — свойства в конструкторе и `?->`

- Запись `private float $amount` прямо в параметрах конструктора сразу создаёт свойство и сохраняет переданное значение. Повторять объявление свойства и присваивание уже не нужно.
- `?Customer` означает: значение может быть объектом `Customer` или `null`.
- `?->` безопасно продолжает цепочку: если слева `null`, результат тоже `null`, а оставшаяся часть цепочки не выполняется.
- `??` задаёт запасное значение, когда результат слева равен `null`.

**Python:** вместо продвижения свойств конструктор обычно пишет `self.amount = amount` (или это генерирует `@dataclass`). Прямого `?->` нет: проверяем `is not None`. Для `??` ближе `x if x is not None else запасное`; Python `x or запасное` ещё заменит `0`, `False` и пустую строку.

В нашем примере без клиента видно «Профиль не найден», а с клиентом и профилем — `42`. Классы `Customer` и `PaymentProfile` добавлены для запуска этого примера.

## Урок 38 — пространства имён (`namespace`)

- Два класса могут называться `Transaction`, если их полные имена различаются: `PaymentGateway\Paddle\Transaction` и `PaymentGateway\Stripe\Transaction`.
- `namespace` объявляет пространство имён для кода в этом файле: `namespace App\Enums\Native;` делает полным именем enum `App\Enums\Native\Status`. Это не импорт; `Native` — обычная часть имени. Папки удобно называть так же, но само имя папки namespace не создаёт.
- `require_once` загружает файл с классом, а `use App\Enums\Native\Status;` позволяет писать короткое `Status` вместо полного имени — похоже на `from app.enums.native import Status` в Python. Сам по себе `use` файл не загружает. В следующем уроке автор переходит к автозагрузке файлов.
- В `use` фигурные скобки группируют классы из одного namespace: `use PaymentGateway\Paddle\{Transaction, CustomerProfile};` — то же самое, что два отдельных `use`.
- `as StripeTransaction` помогает использовать в одном файле оба класса `Transaction`.
- Если внутри namespace нужен встроенный класс PHP, его можно указать от корня: `new \DateTime()`.

**Python:** пространство имён похоже на имя модуля или пакета, например `payment_gateway.paddle.Transaction`. `use ... as ...` похоже на `from ... import ... as ...`, но Python `import` ещё выполняет загрузку модуля.

Пример: открой `http://localhost:8001/namespaces.php` — `var_dump()` покажет объекты из двух разных пространств имён.

## Урок 39 — автозагрузка, PSR-4 и Composer

- `spl_autoload_register()` вызывает нашу функцию, когда PHP встречает ещё не загруженный класс, интерфейс или трейт. Загрузчиков может быть несколько: PHP пробует их по порядку; аргумент `prepend: true` ставит загрузчик в начало очереди.
- В `manual-autoload.php` полное имя `App\PaymentGateway\Paddle\Transaction` превращается в путь `app/PaymentGateway/Paddle/Transaction.php`. `__DIR__` задаёт путь от текущего файла, а `is_file()` не даёт `require` выдать предупреждение при отсутствии файла. Автор приводит `App` к нижнему регистру через `lcfirst()`; мы убираем префикс `App\` и подставляем `app/` — итоговый путь тот же.
- **PSR-4 — правило, по которому загрузчик находит файл класса по его полному имени.** В `composer.json` мы записали `"App\\": "app/"`. Это значит: «если имя класса начинается с `App\`, ищи его файл внутри папки `app/`». Два слеша `\\` в JSON обозначают один слеш `\` в имени класса.

  Например, PHP нужен класс `App\PaymentGateway\Paddle\Transaction`. Composer убирает начало `App\`, получает `PaymentGateway\Paddle\Transaction`, заменяет `\` на `/` и ищет `src/app/PaymentGateway/Paddle/Transaction.php`. В этом файле действительно объявлены `namespace App\PaymentGateway\Paddle;` и `class Transaction`.

  После изменения **самого правила** в `composer.json` запускаем `composer dump-autoload`. При добавлении нового класса в уже настроенную папку `app/` повторять команду обычно не нужно. `use` только сокращает имя класса в PHP-коде; файл находит загрузчик.
- `require vendor/autoload.php` подключает загрузчик Composer один раз. Он находит и наши классы, и классы установленной библиотеки `ramsey/uuid`.
- `composer require ramsey/uuid` добавляет библиотеку и её собственные зависимости. `composer.json` можно создать и командой `composer init`; `composer update` обновляет подходящие версии, `composer remove` удаляет зависимость.
- `require` в `composer.json` — зависимости приложения, `require-dev` — инструменты для разработки и тестов. При `composer install --no-dev` зависимости из `require-dev` не устанавливаются.
- Composer записывает точные версии всех зависимостей в `composer.lock`: его сохраняем в Git. Команда `composer install` берёт эти версии и создаёт `vendor/`; эту папку в Git не добавляем.
- `composer dump-autoload -o` заранее строит карту классов для ускорения загрузки. Новые классы по умолчанию всё ещё находятся через PSR-4; повторный запуск нужен, чтобы добавить их в оптимизированную карту.
- PSR — рекомендации PHP-FIG. PSR-1 и PSR-12 описывают стиль PHP-кода; PSR-4 отвечает за автозагрузку. Автор показывает, что PhpStorm может автоматически форматировать код по PSR-12.

**Python:** Composer для зависимостей похож на `uv`: `composer.json` задаёт требования, `composer.lock` фиксирует версии. PSR-4 с `vendor/autoload.php` ищет PHP-файл по имени класса; Python обычно загружает модуль явным `import`.

Посмотри оба варианта: [ручная автозагрузка](http://localhost:8001/manual-autoload.php) и [Composer с UUID](http://localhost:8001/composer-autoload.php). После клонирования проекта запусти `docker compose -p learnphptherightway -f docker/docker-compose.yml up -d --build`, затем `docker compose -p learnphptherightway -f docker/docker-compose.yml exec app composer install`.

## Урок 40 — константы класса

- `public const PAID = 'paid';` хранит неизменяемое значение, общее для класса. По соглашению имя константы пишут заглавными буквами. Читать её можно без объекта: `Status::PAID`. `::` называется **оператором разрешения области видимости** (англ. *scope resolution operator*). Здесь он даёт доступ к константе класса.
- У константы может быть видимость `public`, `protected` или `private`. Если ничего не написать, она `public`; автор советует указывать видимость явно. `private` нельзя прочитать снаружи класса.
- `self` означает класс, в котором написан код: внутри `Status` запись `self::PAID` равна `Status::PAID`. Это похоже на `Status.PAID` в Python. Не путай с Python `self`: ему в PHP соответствует `$this`, то есть конкретный объект. В `setStatus(): self` слово `self` означает тип возвращаемого значения — `Transaction`.
- `class` в `class Transaction` объявляет класс. А `Transaction::class` — другая запись: она возвращает строку с полным именем класса, например `App\PaymentGateway\Paddle\Transaction`.
- Вместо строки `'paid'` в разных местах используем `Status::PAID`: так меньше риск опечатки. Но метод всё ещё может получить произвольную строку, поэтому `setStatus()` отдельно проверяет её по `Status::ALL_STATUSES` и отклоняет неизвестные значения.
- `ALL_STATUSES` — массив-константа: ключи служат допустимыми статусами, значения — подписями для вывода. Автор сначала хранит статусы в `Transaction`, затем переносит их в отдельный класс `App\Enums\Status`.
- В исходном примере урока PHP 8.0.2, поэтому `Status` — обычный класс с константами. Встроенный `enum` появился в PHP 8.1. Наш Docker-контейнер теперь использует PHP 8.4.

**Python:** `Status::PAID` похоже на `Status.PAID`, но обычный атрибут класса Python можно изменить, а PHP `const` — нет. Наш `enum Status: string` ближе к Python `Enum`: `Status::Paid->value` соответствует `Status.PAID.value`.

Пример: [class-constants.php](http://localhost:8001/class-constants.php) показывает `paid`, начальный статус `pending`, смену на `paid`, подпись `Paid` и полное имя класса.

## Урок 41 — статические свойства и методы

- Обычное свойство (`$status`) принадлежит одному объекту: у двух `Transaction` могут быть разные статусы. Статическое свойство (`private static int $count`) принадлежит классу: счётчик общий для всех `Transaction` в текущем PHP-запросе. В Python это похоже на атрибут класса.
- Снаружи к статическому обращаемся через имя класса: `Transaction::getCount()`, а к открытому статическому свойству — `Transaction::$count`. У нас `$count` закрыт (`private`), поэтому читаем его через `public static function getCount(): int`. Внутри класса пишем `self::$count`.
- Конструктор увеличивает `self::$count` при создании объекта. Статический метод можно вызвать без объекта, поэтому `$this` внутри него недоступен. Обычное свойство нельзя читать как `Transaction::$status`, а обычный метод нельзя вызывать как `Transaction::setStatus()`.
- Автор показывает упрощённый `Db::getInstance()`: закрытый конструктор и статическое свойство хранят один объект для повторных вызовов. Это учебный пример паттерна singleton, не готовый класс для подключения к базе. В новом PHP-запросе статическое состояние начинается заново.
- Статические методы встречаются также у утилит и фабрик; статические свойства — у счётчиков и кешей. Автор предупреждает: изменяемое общее состояние усложняет тесты и поддержку, поэтому не стоит делать всё статическим. Он предлагает предпочитать передачу зависимостей, когда объекту нужны другие компоненты.
- Статический метод технически можно вызвать через объект, но запись через имя класса понятнее. Отдельный случай — замыкание, созданное внутри обычного метода объекта: `function () { return $this->getStatus(); }` видит этот объект. Если написать `static function () { return $this->getStatus(); }`, вызов даст ошибку: `static` не привязывает к замыканию `$this`. Так автор защищается от случайного изменения объекта в callback. Это не связано с общим счётчиком `$count`.

**Python:** `count = 0` в теле класса — аналог общего статического свойства. `getCount()`, который читает счётчик класса, ближе к `@classmethod` с `cls.count`; PHP `static`-метод без работы с состоянием класса ближе к `@staticmethod`. У `static function () {}` для замыкания прямого синтаксического аналога в Python нет.

Открой [пример урока 41](http://localhost:8001/static-properties.php): два объекта имеют разные статусы, общий счётчик равен двум, а повторный `Db::getInstance()` возвращает тот же объект.

## Урок 42 — инкапсуляция и абстракция

- Автор называет четыре принципа ООП: инкапсуляция, абстракция, наследование и полиморфизм. В этом уроке разбирает первые два.
- **Инкапсуляция**: объект хранит свои данные и методы вместе и сам решает, как менять своё состояние. В учебном `Transaction` сумма `private`: снаружи нельзя написать `$transaction->amount = 125`. `public` доступен всем, `private` — только коду этого класса, `protected` — ещё и классам-наследникам (их разберём позже).
- Автор сначала показывает `getAmount()` и `setAmount()`, затем убирает ненужные методы: если сеттер без ограничений меняет сумму после создания, он возвращает прежнюю проблему. Для другой суммы можно создать другой `Transaction`. Геттеры и сеттеры нужны, когда есть реальная причина — например, проверка, форматирование или цепочка вызовов (*fluent interface*); публичные свойства тоже бывают у простых объектов для передачи данных (DTO).
- В нашем примере `process()` — публичное действие, а `formatAmount()` — приватная внутренняя деталь. **Абстракция** здесь означает: вызывающий код знает, что делает `process()`, но ему не нужно знать, как внутри оформлена сумма. Реализацию `formatAmount()` можно поменять, не меняя вызов `process()`. Это принцип ООП, а не ключевое слово `abstract` из будущего урока.
- Автор показывает `ReflectionProperty`: им можно прочитать и изменить даже `private`-свойство. В PHP 8.4 `setAccessible(true)` из старого видео уже не нужен — начиная с PHP 8.1 он ничего не меняет. Reflection здесь только демонстрирует границу ограничения, обычный код так состояние не меняет.
- Бонус автора: внутри временного метода `copyFrom(Transaction $other)` он читает `$other->amount` и вызывает приватный метод другого объекта того же класса. Название `copyFrom` здесь лишь часть демонстрации: в видео автор не сравнивает суммы и не копирует их.

**Python:** `self._amount` и `_format_amount()` обычно обозначают «внутреннее, не трогай снаружи» по соглашению; `self.__amount` дополнительно меняет имя атрибута, но не создаёт строгий PHP `private`. Публичный `process()` может вызывать внутренний `_format_amount()` — та же идея абстракции. Для контролируемого чтения свойства в Python есть `@property`.

Открой [пример урока 42](http://localhost:8001/encapsulation.php): сначала обработка суммы 25, затем отдельной суммы 125 и демонстрация Reflection.
